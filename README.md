# 麻雀セットルール集

セットで使用する麻雀ルールを、ルールごとのTypst文書として管理するリポジトリです。

各ルールは独立したフォルダに置き、卓上で参照できるPDFも同じフォルダに保存します。ローカルルールの差異を曖昧にせず、採用した内容と参照元が分かる文書を目指します。

## 収録ルール

| ルール | Typst | PDF |
|---|---|---|
| 5等サンマ | [rule.typ](5等サンマ/rule.typ) | [rule.pdf](5等サンマ/rule.pdf) |

## ディレクトリ構成

```text
mahjong-rule/
├─ README.md
├─ 5等サンマ/
│  ├─ rule.typ
│  ├─ rule.pdf
│  └─ assets/
│     └─ season-table.png
└─ ＜別のルール＞/
   ├─ rule.typ
   ├─ rule.pdf
   └─ assets/
```

ルールフォルダ内では、次の名前を共通で使用します。

- `rule.typ`: 編集元となるTypst文書
- `rule.pdf`: 配布・印刷用の生成物
- `assets/`: 画像など、そのルールだけで使う素材

## 新しいルールの追加方法

1. リポジトリ直下に、ルール名を表すフォルダを作成します。
2. フォルダ内に `rule.typ` を作成します。
3. 必要な画像は同じフォルダの `assets/` に置きます。
4. 公開されている雀荘ルールなどを複数確認します。
5. 採用例が分かれる項目は、勝手に混ぜず、採用する方式を決めてから記載します。
6. 文末に参照元と閲覧日、独自に調整した項目を記載します。
7. PDFを生成し、文字切れ、表のはみ出し、不自然な改ページがないか確認します。
8. このREADMEの「収録ルール」へリンクを追加します。

既存ルールを雛形としてコピーする場合も、点数、祝儀、罰則、終局条件、特殊役などを新しいルールに合わせて必ず見直してください。

## ビルド

[Typst](https://typst.app/)をインストールし、リポジトリのルートで実行します。

```powershell
typst compile "5等サンマ\rule.typ" "5等サンマ\rule.pdf"
```

### Dockerを使う場合

Typstをローカルへインストールしなくても、Docker Composeでビルドできます。Dockerイメージには文書で使用するNoto Sans CJK JPフォントも含まれるため、OSに依存せず同じ書体で出力されます。リポジトリのルートで次を実行すると、初回はビルド用イメージを作成し、すべてのルールをビルドします。

```sh
docker compose run --rm typst-all
```

WSLから実行する場合は、Windows側に置いたこのリポジトリへ移動してから実行します。たとえばリポジトリが`C:\Users\名前\src\mahjong-rule`にある場合、WSL上のパスは通常`/mnt/c/Users/名前/src/mahjong-rule`です。

```sh
cd /mnt/c/Users/名前/src/mahjong-rule
docker compose run --rm typst-all
```

特定のルールだけをビルドする場合は、そのルールのサービスを指定します。

```sh
docker compose run --rm typst-gotou
```

リポジトリはコンテナの`/work`へ自動的にマウントされるため、生成された`rule.pdf`はWindows側の同じフォルダへ直接保存されます。パスに空白や日本語が含まれる場合は、Typstファイルのパスを引用符で囲んでください。

新しいルールを追加するときは、`compose.yml`へルール専用サービスを追加します。たとえば`新ルール/rule.typ`を追加した場合は次のように定義します。

```yaml
services:
  typst-new-rule:
    <<: *typst-service
    command:
      - |
        typst compile --root /work "新ルール/rule.typ" "新ルール/rule.pdf"
```

さらに、`typst-all`の`command`にもコンパイルコマンドを追加します。コマンドは上から順番に実行され、途中で失敗した場合は`-e`オプションにより、その時点で全体ビルドも失敗します。

```yaml
  typst-all:
    command:
      - |
        typst compile --root /work "5等サンマ/rule.typ" "5等サンマ/rule.pdf"
        typst compile --root /work "新ルール/rule.typ" "新ルール/rule.pdf"
```

コンテナは作業ファイルをイメージへコピーせず、Windows側のファイルをバインドマウントして読み書きします。このリポジトリは扱うファイル数が少ないため、WSLのLinuxファイルシステムへ移すことを前提にはしていません。

## 記載方針

- セット開始前に合意が必要な事項を明文化します。
- 点数表や祝儀は、計算方法だけでなく具体的な数値も掲載します。
- 「一般的」「通常」だけで済ませず、このセットでの裁定を記載します。
- 店舗ごとに異なる内容は、どの方式を採用したか明記します。
- 出典のルールをそのまま採用した部分と、セット向けに変更した部分を区別します。
- 内容を変更したら `rule.pdf` も再生成し、見た目を確認します。
- チップはゲーム内得点として扱い、賭博を目的としません。

## 変更時の確認項目

ルールを追加・変更するときは、少なくとも次を確認します。

- 使用牌、赤牌・金牌・花牌・白ポッチの構成
- 持ち点、返し点、ゲーム形式、連荘・終局条件
- 符計算、ツモ損、満貫以上の点数表
- ドラ、抜き牌、特殊牌の効果
- 採用役、ローカル役、役満の複合
- 祝儀、チップ、順位点、トビ賞
- 途中流局、ダブロン、パオ、オープンリーチ
- 誤発声、少牌・多牌、チョンボなどの罰則
- 4人で卓を回す場合の抜け番の扱い
- 出典URL、閲覧日、セット独自の変更点
